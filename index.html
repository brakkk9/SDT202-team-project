01 — PROBLEM

What are we solving?

A set S = {a1, …, an} of activities wants to use one shared resource (e.g. a CPU core) that serves one activity at a time.

Each activity occupies the interval [si, fi), where 0 ≤ si < fi.

ai and aj are compatible if fi ≤ sj  or  fj ≤ si

Goal: select a maximum-size subset of mutually compatible activities.

02 — ALGORITHM

Greedy: earliest finish first

  1. Sort activities by finish time.
  2. Select the first one; remember its finish time.
  3. For each next activity: if si ≥ lastFinish, select it; otherwise skip.

Optimal substructure — after a choice, the rest is the same smaller problem.

Greedy choice — finishing earliest leaves the most time for the rest.

Time O(n log n) · DP alternative O(n²)

04 — REAL-WORLD SITUATION

Robotic surgery operating room

Departments submit non-emergency robotic surgery requests each morning. Only one team can use the room at a time — the coordinator wants as many surgeries as possible in one day.

05 — RISKS

What could go wrong

1

Edge cases. Activities that end exactly when another starts, or finish at the same time. → One consistent comparison, tested.

2

Invalid input. Wrong time formats or end before start. → Check every request, report bad ones.

3

Count vs. importance. The algorithm maximises the number of activities, not their importance.
